Suggested Integration Methods

The capability map above shows what the platform does. The section below suggests a primary integration method for each capability so you can demonstrate a mix of integration patterns across the landscape.

These recommendations assume a modern application estate where:

  • synchronous reads and transactional updates are best handled through APIs
  • business notifications and process state changes are better distributed through events
  • external channel updates are often best exposed through webhooks
  • high-volume or scheduled exchanges are often best handled through batch file integration

Integration Pattern Overview

Pattern Key

Method Use when
REST API A consuming system needs synchronous create, update, or query behaviour.
GraphQL API A consuming experience needs flexible read access across related entities.
Event Bus Multiple systems need to react to a business event without tight coupling.
Webhook An external platform needs to be notified immediately when something changes.
Message Queue Work should be processed asynchronously and reliably, often with retries.
Batch File / SFTP Large scheduled data exchanges are acceptable and near-real-time is not required.
Change Data Capture Downstream analytics or integration services need a stream of data changes.

Example End-to-End Demonstration Story

If you want to show different integration methods working together in one scenario, a simple narrative would be:

  1. A web channel submits a new enquiry through a webhook into Manage web enquiries.
  2. A user captures applicant requirements through a REST API.
  3. Matching logic publishes a match event on the event bus.
  4. Applicant communications are queued through a message queue.
  5. A portal listing is pushed to an external site through a webhook.
  6. Offer creation happens through a REST API, which emits an Offer Recorded event.
  7. Compliance and reporting consume that event, while dashboards update through change data capture.

Design Note

Each capability has a suggested primary method, not an exclusive one. In practice, the most robust architecture often combines methods, for example REST API for command, Event Bus for notification, and Change Data Capture for analytics.
